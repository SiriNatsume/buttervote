# 性能优化第三轮（2026-10-22）

本轮覆盖计票与候选权限、活动/投票页请求、公开历史结果缓存、Worker 运行位置，以及分享 PNG 缓存。页面布局、计票规则、投票资格、个人状态、报票推进和结果可见性继续使用原有规则。

## 计票和请求

`get_visible_contest_tallies` 先按活动及候选 ID 汇总展开后的票数，再连接受 RLS 保护的候选项，保留无票候选、停用候选管理员覆盖、真爱权重和末票时间。`can_read_candidate` 将谱系中的源活动可见性合并读取，仍拒绝循环、丢失来源及隐藏来源。十条原有身份策略改用语句级 `(select auth.uid())`，未改变条件或角色。

活动详情通过外键关系同时读取活动组，结果可见性、个人选票和参与资格并行加载。已经读取活动组的服务端页面复用该请求内的组配置；提交操作继续重新核验权限。公开历史候选与计票复用同一请求内的快照，实时活动的查询立即开始。

## 公开结果缓存

- 仅 `published` 且当前允许公开完整结果的活动可以进入缓存。资格由匿名客户端每次请求读取 `public_result_cache_versions` 的 RLS 重新确认，包括来源继承、归档及报票状态。管理员覆盖和个人数据不参与缓存。
- `get_public_result_snapshots` 在同一个 MVCC 快照里验证期望版本并读取候选和汇总，不返回原始选票、个人资料或报票事件。版本变化、撤回或结果不完整时不缓存，页面回退到原有 RLS 读取。
- 已发布活动的候选、选票、真爱票、活动元数据和组权重变更会更新版本。投票中的活动不会在每次投票时争用这个版本行；发布时建立新版本。
- 每个活动占用私有 R2 中一个缓存槽，内容带版本及一小时过期时间；请求内复用，Worker 内存 LRU 上限 8 MiB、单项 4 MiB。现有认证定时接口在后台每次清理最多 250 个槽的一页，游标续扫，只处理本功能前缀中已过期的对象。R2 不可用时继续正常读取，缓存故障不能授权访问旧数据。
- 活动组首页、组内结果和独立结果页使用公开快照。所有 HTML 保持动态，进行中的计票与个人投票记录继续即时读取。

## 分享图

报票图和对阵图在完成当次权限及可见版本检查、构造完整 SVG 后，以 SVG 的 SHA-256 作为内容版本缓存 PNG。每个活动/活动组只有一个私有槽；不同卡片会替换该槽，不能因历史步数无限增长。并发生成相同内容会合并，失败不缓存。浏览器响应保持 `no-store`，缓存不能绕过未来卡片、归档或版本检查。

字体按完整字符集合排序，卡片顺序和数字顺序变化可以复用字体子集；字体 Promise 使用有界 LRU。生产环境继续拒绝缺少显式字体的渲染。更改快照协议、计票输出语义或 PNG 渲染/字体契约时，应更新相应缓存命名空间，避免复用旧格式。

WASM 由现有 Worker 入口静态导入预编译模块，随请求环境交给 OpenNext，避免依赖 Next.js 将共享代码放在路由文件还是独立 chunk。普通本地 Next 开发继续读取包内 WASM。

## Placement 对照

`scripts/benchmark-worker-placement.mjs` 创建两个带随机令牌的临时探针，通过 Service Binding 调用同一个已部署的 `vote-site`，分别使用默认边缘位置和新加坡提示。只接受明确的公开页面 GET，转发时不携带调用者 Cookie/令牌；不复制生产 secrets。两组读取完整 HTML 并核对标题摘要，结束后已清理探针，报告不包含令牌或 HTML。

每页预热三对，再交替采样十二对。以下为本次请求出口的 `clientMs`，包括探针往返、新加坡转发及服务端取回完整 HTML，不包含浏览器静态资源下载、水合和交互：

| 页面 | 默认位置 P50 / P95 | 新加坡 P50 / P95 |
| --- | ---: | ---: |
| 首页 | 742 / 905 ms | 642 / 1023 ms |
| 历史活动组 | 1521 / 1956 ms | 1387 / 1724 ms |
| 活动组结果 | 1345 / 1866 ms | 1304 / 1505 ms |

新加坡通过 `cf-placement: remote-SIN` 确认；默认组没有位置提示。因首页尾部延迟存在波动，本轮采用 `placement.mode = "smart"` 自动选址，让平台按真实请求时长评估并保留基线对照；不固定所有请求到新加坡，也不把本次样本解释成全网收益。初次评估可能需要约十五分钟，流量不足时可以保持默认位置。参见 [Cloudflare Placement](https://developers.cloudflare.com/workers/configuration/placement/) 和 [Service Bindings](https://developers.cloudflare.com/workers/runtime-apis/bindings/service-bindings/)。

## 验证和发布

- 174 项回归全部通过，包含缓存版本、过期、限额、存储故障、并发生成、权限撤回、加载中变更、损坏缓存及有界清理；类型检查、变更文件 ESLint（零错误、五条原有图片提示）、OpenNext 生产构建和 Wrangler 部署预检通过。
- 本地 9000 张基础选票覆盖三种投票方式和小数真爱权重，并与原计票函数及 JavaScript 算法核对。另验证未知/跨活动候选、重复多选及异常排名保持原有处理方式。
- 简单原生候选的计票 HTTP 样例中位数为 29 → 29 ms，未声称该场景有可测加速。六层继承样例的数据库执行时间中位数为 6.924 → 5.796 ms；这些局部数字不代表整页速度。
- 热缓存仍执行权限/版本读取；改名、权重、选票、报票、继承及归档变更已验证。真实管理员也无法通过公开缓存读取被报票遮蔽的完整结果，管理员原有覆盖读取仍可用。
- 本地实际 PNG 接口：普通访客未来步数在管理员预热前后均返回 404；当前步数重复响应字节一致且保持 `no-store`。开发环境连续两次公开卡请求为 528 / 62 ms，本地生产 workerd 为 403 / 48 ms，不作为生产延迟承诺。
- 浏览器实际提交独立投票和恰选两项联合投票成功；受限活动的资格授予及撤回在下一次读取生效，缓存改名和报票遮蔽即时呈现，未发现新增浏览器错误。结果可见性与报票广播集成检查通过。
