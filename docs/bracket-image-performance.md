# 分享对阵图性能与缓存

图片样式、2880 × 1620 分辨率和赛程页组件保持原样。完整人外杯的优化前后公开数据一致，SVG 已逐字节核对。

## 读取和权限

`get_bracket_image_export_state` 是只读、`SECURITY INVOKER`、仅允许 `service_role` 执行的 RPC；浏览器和普通管理员不能直接调用。HTTP 请求另外使用调用者的 Supabase 客户端读取活动组，继续受组 RLS 约束。RPC 固定调用 `get_contest_result_visibility(..., false)`，后台预生成也使用匿名客户端，没有管理员覆盖。

一次 MVCC 快照读取赛程结构、候选继承、公开状态和版本。需要成图时，同一 RPC 按期望版本返回快照，计票复用现有 `get_visible_contest_tallies`，不再传输原始选票后重新计票。快照与期望版本不一致时不生成旧版本图片。

缓存指纹覆盖赛事和活动组数据、比赛及参赛条目、候选与完整来源链、统一可见性、已发布结果版本，以及 Storage 对象的版本、更新时间和元数据。因此改名、改分、改权重、排名、归档、上游唱票及同路径替换头像都能在下一次读取时失效。实时投票和未完全公开的数据不使用提前成图缓存，避免为活跃投票增加一个争用的版本写入点。

## 图片和素材

当前权限和数据库指纹检查通过后，才读取私有 R2 成图缓存；命中时跳过头像、字体和渲染。读取 R2 后、冷渲染后和缓存写回后均重新校验权限及指纹，过程中发生撤回或修改则返回 404/409，不返回刚才的旧图。客户端仍收到 `private, no-store`。每组只有一个成图槽，渲染协议由 `BRACKET_EXPORT_RENDER_VERSION` 标识，修改布局、尺寸或字体渲染时必须递增该版本。

头像以 Storage 对象版本缓存到现有私有 R2，每个 URL 一个可替换槽。请求上游图片时附带版本参数，避免同路径覆盖后仍读到旧 CDN 内容。缺失版本或下载失败时不使用该头像的持久缓存，缺少素材或比分的降级图片不进入提前成图缓存。

字体 CSS 和实际字体文件也使用私有 R2，并保留有界进程内缓存。只接收 Google Fonts 的预期字体 URL 和字体格式，失败响应不缓存。下载期限覆盖响应体，防止头部已返回而字体内容一直停滞。所有资源沿用现有缓存的容量限制与过期清理。

## 预生成

管理员发布赛果或显式完成唱票后，通过现有 Cloudflare `waitUntil` 在后台预生成稳定公开的图片，不阻塞发布操作。认证分钟 cron 每次顺序处理至多三个推荐赛事，使用私有游标轮转；单组失败不会阻塞其他组，也会在后续轮次重试。预生成与用户导出使用同一个权限检查和缓存流程。

## 验证与发布

使用 Node.js 22+，先把本迁移应用到本地 Supabase，再运行：

```sh
npm test
npm run typecheck
npm run test:bracket-export:local
```

本地集成测试使用自建并清理的样例，覆盖小数真爱权重、改票、改名、排名、同路径头像覆盖、快照竞争、上游唱票、管理员隔离、实时基础分、组 RLS 撤回和来源归档。`--keep-fixture` 可为本机 workerd 接口检查保留该专用样例。

审查通过后，先按迁移名称核对并应用 `20261023123209_bracket_image_export_cache.sql`，再合并 PR，由 Cloudflare Workers Builds 发布。迁移只增加服务端只读函数，不改变投票、发布或权限表的写入逻辑。上线后验证真实分享按钮、PNG 尺寸、`no-store` 及 `Server-Timing` 的 HIT/MISS/LIVE 状态。
